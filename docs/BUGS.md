# FireCAE Bug 记录

## UI-002：OpenCascade 视口停留在临时 100×30 尺寸

- 状态：已修复（2026-08-27）
- 模块：OpenCascade 3D Viewer / Qt 原生窗口
- 严重程度：高

### 现象

主界面打开后，中央区域大部分为黑色，仅左下角出现约 100×30 个 Qt 逻辑像素的灰色 OpenCascade 渲染区域；最大化窗口后仍未铺满。

### 根因与修复

`OccViewWidget` 在 `QStackedWidget` 完成首次布局前同步初始化 OCCT，OpenGL 视口因此记录了 QWidget 的临时默认尺寸。现改为事件循环开始后再初始化，并在首次布局、窗口缩放以及最大化完成后同步 Win32 子窗口和 OCCT 视口尺寸，同时强制使渲染内容失效并重绘。

### 验收结果

- 普通窗口下，OCCT 背景完整覆盖中央视图。
- 最大化至 1600×952 后，视口继续完整覆盖中央视图，没有左下角灰色小矩形。
- 创建 `Box_001` 后，几何体在完整视口中居中显示。
- FireCAECoreTests 与 FireCAEUiTests 共 2 项测试全部通过。

## UI-001：主窗口停靠区域显示比例异常

- 状态：已修复（2026-08-27）
- 记录日期：2026-08-27
- 模块：主窗口 / Dock 布局 / 中文界面
- 严重程度：中
- 发现阶段：P02 验收后

### 现象

启动 FireCAE 或打开主界面后，左侧“模型树”和“属性”停靠区域宽度异常过窄。中文模型树节点只能显示开头的少量字符，大部分文字被裁切；中央 3D 视图占用比例过大，整个主窗口的区域比例失衡。

### 复现条件

1. 启动 `FireCAE.exe`。
2. 将界面语言切换为简体中文，或在已保存中文语言设置的情况下重新启动。
3. 观察左侧模型树、属性面板与中央 3D 视图的宽度比例。

### 实际结果

- 左侧 Dock 宽度接近其最小宽度。
- “几何、网格、材料、表面、反应、设备、HVAC、输出、结果”等节点文本被明显裁切。
- 中央 3D 视图相对过宽。

### 预期结果

- 首次启动和恢复窗口布局后，左侧 Dock 应保持可用的默认宽度。
- 中英文界面下，模型树的常用节点名称应完整显示。
- 主窗口缩放或 DPI 变化后，各区域比例应保持合理。

### 初步排查方向

- 检查 `QMainWindow::restoreState()` 是否恢复了旧版本保存的异常 Dock 宽度。
- 检查窗口首次显示后是否调用了 `resizeDocks()`，以及调用时机是否正确。
- 检查模型树和属性面板的 `minimumWidth`、`sizeHint`、`minimumSizeHint` 与 `QSizePolicy`。
- 检查中英文切换后是否需要重新计算 Dock 的最小宽度。
- 在 Windows 显示缩放 100%、125%、150% 下分别验证高 DPI 布局。

### 验收标准

- 清除设置后的首次启动布局正常。
- 使用已有设置升级启动时也能修正过窄布局。
- 中文和英文切换后，左侧 Dock 不会自动收缩。
- 典型窗口尺寸及 Windows 常用 DPI 缩放下，模型树常用节点不被裁切。

### 修复结果

- 初始主窗口按当前屏幕可用区域的 86% 计算并居中，最大限制为 1280 × 820 个 Qt 逻辑像素，避免在 150% 缩放下接近全屏。
- 左侧模型树/属性区按主窗口宽度的 20% 计算，并限制在 190～280 个逻辑像素；底部消息区同样按比例限制在 140～190 个逻辑像素。
- 布局在停靠窗口创建后及事件循环开始时各校正一次，避免 Qt 首次布局覆盖目标尺寸。
- 自动化测试覆盖窗口尺寸上限、可用桌面范围和停靠区宽度范围；本机实际启动验证通过。

## P02-001：Smokeview 动画窗口缺少可见播放控制按钮

- 状态：待处理
- 记录日期：2026-08-27
- 模块：P02 后处理 / Smokeview 动画交互
- 类型：功能缺口
- 严重程度：中

### 现象

从 FireCAE 打开烟气/火焰动画后，Smokeview 能够加载数据并推进帧，底部也显示时间条、帧号和时间，但窗口中没有可见的播放、暂停、上一帧、下一帧、停止等按钮。用户必须知道 Smokeview 的快捷键或时间条操作方式，交互不直观。

### 当前临时操作

- 在 Smokeview 窗口获得焦点后，使用空格键切换播放与暂停。
- 点击或拖动底部时间条跳转到相应时间。
- 其他数据和显示选项通过 Smokeview 右键菜单操作。

### 预期结果

- 用户无需记忆快捷键即可找到播放和暂停入口。
- 至少提供播放/暂停、上一帧、下一帧、回到首帧以及当前时间反馈。
- 控件应明确作用于当前由 FireCAE 启动的 Smokeview 实例。

### 技术约束

当前采用独立进程启动原生 Smokeview，FireCAE 无法像控制 Qt 内部控件一样直接控制其时间状态。简单模拟键盘输入依赖窗口焦点，可靠性不足。实现前应在以下路径中作出选择：

1. 保持原生 Smokeview，在 FireCAE 中增加操作提示和快捷入口。
2. 为 Smokeview 增加原生工具栏并维护 FireCAE 专用构建。
3. 建立明确的进程间控制接口，再由 FireCAE 提供播放工具栏。

### 验收标准

- 动画窗口中存在清晰可见、可点击的播放控制。
- 播放、暂停和逐帧操作可重复执行且状态一致。
- 多个算例窗口同时打开时，控制命令不会发送到错误窗口。
- 不依赖 Smokeview 窗口恰好拥有键盘焦点。

## P02-002：Smokeview 结果窗口未集成到 FireCAE 主界面

- 状态：待决策
- 记录日期：2026-08-27
- 模块：P02 后处理 / 主界面集成
- 类型：产品体验与架构需求
- 严重程度：中

### 现象

用户从 FireCAE 打开 FDS 结果后，Smokeview 以独立的 Windows 顶层窗口运行，结果画面不会显示在 FireCAE 主界面的中央视图区。用户需要在两个窗口之间切换，界面体验不统一。

### 当前原因

P02 当前采用“外部进程启动原生 Smokeview”的既定技术路线。Smokeview 是独立应用程序，拥有自己的窗口、OpenGL 渲染循环、输入事件和菜单系统，并不是可直接放入 Qt 布局的 `QWidget`。

### 目标体验

- 在 FireCAE 主窗口中切换“建模”和“结果”工作区。
- 结果动画显示在中央视图区。
- 播放控制、时间、数据类型和图例由 FireCAE 统一管理。
- 用户无需在 FireCAE 与外部 Smokeview 窗口之间切换。

### 可选技术路线

1. **Windows 窗口句柄嵌套**：使用原生窗口句柄和 `SetParent` 将 Smokeview 窗口临时挂入 Qt。开发较快，但容易出现焦点、DPI、尺寸、菜单、快捷键、崩溃隔离和多窗口问题，不建议作为正式架构。
2. **改造 Smokeview 为可嵌入渲染组件**：维护 FireCAE 专用 Smokeview 分支，拆分窗口和渲染循环，提供 Qt/OpenGL 宿主接口。工作量大，且后续合并上游升级成本高。
3. **开发 FireCAE 原生后处理视图**：在 Qt 中自行读取 FDS 结果并渲染烟气、火焰、切片和粒子。体验最好、控制能力最强，但属于长期后处理模块建设。
4. **混合模式**：FireCAE 内置常用结果查看和播放功能，同时保留“在 Smokeview 中打开”用于高级功能和结果校核。

### 推荐方案

采用混合模式：短期保留独立 Smokeview，保证 FDS 全结果类型可用；随后开发 FireCAE 原生结果工作区，优先实现时间轴、播放控制、Slice 和基础烟气显示。不要把 `SetParent` 窗口嵌套作为长期产品方案。

### 验收标准

- 主界面中央区域可切换到结果查看工作区。
- 结果工作区具备可见的时间轴和播放控制。
- 打开、关闭或切换结果不会破坏建模视图状态。
- 仍保留独立 Smokeview 启动入口作为兼容和高级查看模式。
